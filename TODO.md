- [ ] **Catalog version consistency** — `@types/node` and `typescript` in `packages/proclaimer/package.json` (and other packages) use direct version specifiers instead of `catalog:`. Update `devDependencies` to use `catalog:` and ensure `pnpm-workspace.yaml` catalog entries match.
- [ ] **Placeholder metadata** — `packages/proclaimer/package.json` (and all other packages: `packages/utils/package.json`, `packages/ui/ionic/package.json`, `tools/config/package.json`) still have placeholder values for `description`, `author`, `homepage`, `bugs.url`, and `repository.url`. Replace with real project metadata.
- [ ] **Missing `<meta charset="UTF-8">` in app `index.html`** — `apps/subbie/index.html` (and `apps/vite-project/index.html`) are missing `<meta charset="UTF-8" />`. The `htmlInject` plugin doesn't inject a charset tag either. Without it, the browser may default to a different encoding, potentially causing rendering issues with non-ASCII characters.
- [x] **`patchData` silently swallows write errors** — `packages/utils/src/app-settings/app-settings.ts` `patchData` catches all errors, logs them to console, and returns the caught promise. This means every write method (`set`, `setMany`, `remove`, `clear`) always resolves even when the underlying RxDB write fails. Callers like `importAppSettings` and the export/import UI components cannot detect or surface write failures to the user. Fix by returning the raw operation promise (or re-throwing) so callers can handle errors.
- [ ] **`importAppSettings` with `replace: true` silently destroys all settings when no keys match** — `packages/utils/src/app-settings/import-app-settings.ts` filters imported keys to only those already in the store. With `replace: true` and no matching keys, it clears the store then writes nothing — the user loses all settings with no error. Consider erroring or warning when `replace` would result in zero imported keys.
- [ ] **`importAppSettings` silently drops unknown keys with no feedback** — `packages/utils/src/app-settings/import-app-settings.ts` filters to only keys that already exist in the store. If a user imports into a fresh install (where defaults haven't been seeded), nothing is imported and the function resolves successfully with no indication. Consider returning a count of imported vs. dropped keys, or erroring when nothing was imported.
- [ ] **`ImportSettingsItem` page reload races with error toast** — `packages/ui/ionic/src/components/settings-transfer/import-settings-item.tsx` calls `window.location.reload()` immediately on success, giving no success feedback. On failure, the error toast (3000ms) may not be seen if the user navigates away. Consider showing a success indicator before reloading, or adding a short delay.
- [ ] **`importAppSettings` type-unsafe cast** — `packages/utils/src/app-settings/import-app-settings.ts` casts `known` to `Partial<T>` without validating that values match the specific types of `T`. Importing `{"theme": "blue"}` when `T` has `theme: "light" | "dark"` passes `isJsonValue` validation and gets written. The RxDB schema uses `additionalProperties: true` with no type constraints, so RxDB won't reject it either.
- [ ] **No file size limit on settings import** — `packages/ui/ionic/src/components/settings-transfer/import-settings-item.tsx` reads the entire file via `file.text()` with no size check. A maliciously large file could cause memory issues. Consider adding a size guard (e.g., reject files > 1MB).
- [ ] **`ExportSettingsItem` provides no success feedback** — `packages/ui/ionic/src/components/settings-transfer/export-settings-item.tsx` only shows errors on failure. On success, the download triggers silently with no toast or confirmation. A brief success toast would improve UX.
- [ ] **`exportAppSettings` only exports stored keys, not defaults** — `store.getAll()` returns only keys that have been explicitly written to RxDB. If defaults change between app versions, old defaults won't be in the export. Worth documenting or handling for version migration scenarios.
- [x] **Missing test for `importAppSettings` write failure** — `packages/utils/tests/settings-transfer.test.ts` has no test for what happens when RxDB writes fail during import. Add a test (mocking or simulating a write failure) once the `patchData` error-swallowing bug is fixed.
